# Anti Slop Audit 002

Date: 2026-09-04  
Mode: AFTER  
Scope: Requested company status filtering and job portal updates

## Design Read

The dashboard follows the operational workspace direction in `DESIGN.md`.

The Companies view uses opening cards for company records.

The existing pipeline toolbar uses compact status controls.

Those controls match the dense operational interface and status color rules.

## Findings

1. **HIGH, R-26: The Companies view cannot filter profiles by status.**  
   Status controls exist only in the Pipeline view.  
   `CompaniesView` always shows every profile for an opening when the user expands it.  
   Evidence: `app/dashboard/dashboard-client.tsx:176-180` and `components/dashboard/companies-view.tsx:12-24`.  
   Repair: Add status controls to the Companies view and filter its visible profiles by the selected statuses.

2. **HIGH, R-26: The Companies view cannot update the job portal application state.**  
   Each opening card shows `Applied on portal` or `Not applied on portal`.  
   The card has no control that changes `applied_on_portal`.  
   The dashboard imports no action that updates this field.  
   Evidence: `components/dashboard/companies-view.tsx:17-18` and `app/dashboard/dashboard-client.tsx:12`.  
   Repair: Add an accessible toggle for `applied_on_portal`, then save the change through an owner-scoped server action.

## Delivery Gate

### Hard Gate: FAIL

R-26 fails for both requested Companies view capabilities.

### Purpose-Gate: PASS

The status controls and opening cards have purposes stated in `DESIGN.md`.

### Liveliness: PASS

The requested controls fit the declared ENERGY 2, RHYTHM 2, and MOTION 1 dials.

### Craftsmanship and Quality Locks: FAIL

The Companies view does not provide the requested task controls.
