# Anti Slop Audit 003

Date: 2026-09-05  
Mode: AFTER  
Scope: Personal greetings and outreach message situations

## Design Read

The dashboard follows the operational workspace direction in `DESIGN.md`.

Message generation happens in a focused drawer for one contact.

The template picker belongs in that drawer because it changes the message task.

The existing profile settings remain the correct place to edit template text.

## Findings

1. **HIGH, R-26: The message template cannot greet a contact by first name.**  
   `renderMessageTemplate` replaces `{name}` with an empty string.  
   The template help also says that name placeholders stay empty.  
   The generated message cannot produce `Hi Abhishek,` for a connection named `Abhishek Kumar`.  
   Evidence: `lib/message-template.ts:21-27` and `app/dashboard/dashboard-client.tsx:237-239`.  
   Repair: Derive the first whitespace-separated part of `connection.name`.  
   Replace `{name}` with that first name.  
   Label the placeholder as `{firstName}` in the editor for clear intent.

2. **HIGH, R-26: The message drawer supports only one outreach situation.**  
   The profile stores one `message_template`.  
   `MessageDrawer` renders that one template without a situation selector.  
   A user cannot select an outreach message for a role already applied for.  
   Evidence: `app/dashboard/dashboard-client.tsx:232-239` and `lib/message-template.ts:3-17`.  
   Repair: Add selectable `Default outreach` and `Applied outreach` templates.  
   Persist both templates in the existing profile field as structured template data.  
   Preserve existing plain-text templates as the default outreach template.

## Decision Reasons

- The situation selector stays in the message drawer because it changes one generated message.
- Profile settings keep template editing because templates remain profile-level preferences.
- First-name greetings use the stored contact name and do not require extra profile data.
- The selector uses standard buttons because the interaction must work with keyboard and touch input.

## Delivery Gate

### Hard Gate: FAIL

R-26 fails for both requested message capabilities.

### Purpose-Gate: PASS

The focused drawer and profile settings match the operational workflow in `DESIGN.md`.

### Liveliness: PASS

The change fits ENERGY 2, RHYTHM 2, and MOTION 1.

### Craftsmanship and Quality Locks: FAIL

The message workflow does not support the requested personalization or applied outreach situation.
